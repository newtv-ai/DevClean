# DevClean 使用说明

Windows 11 磁盘清理工具，专门针对**开发工具与 AI 软件产生的缓存**——pip、uv、npm、pnpm、Yarn、Docker、Android 模拟器、Ollama、Claude、Codex、JetBrains、VS Code 及其分支等。这些位置是通用清理软件基本不覆盖的，而在开发机上它们往往是占地方的主体。

## 装什么都不用装

`DevClean.exe` 自带 Python 运行时。不需要装 Python、不需要虚拟环境、不写注册表、不留后台服务。

双击 → 允许 UAC 提权 → 用完关掉即可。

程序产生的持久文件全部集中在 EXE 旁边的 `DevClean-data`：三份规则、默认规则备份、AI 导入索引和有上限的删除意图日志都在其中，不写入 AppData。删除 `DevClean.exe` 和旁边这个文件夹就是完整卸载。源码运行时放在项目根目录的 `DevClean-data`。单文件 EXE 启动时由 PyInstaller 使用的 `_MEI...` 是进程临时解包目录，不是配置位置；活动规则首次复制到 `DevClean-data` 后，正常载入和编辑只读取同目录文件。如果用户单独删掉默认备份 ZIP，程序会从当前 EXE 自带的原始模板重新生成备份，但不会覆盖三份活动规则；即使重建失败，活动规则仍可正常载入。

**为什么要管理员权限**：`C:\Windows\Temp`、`SoftwareDistribution\Download`、`Prefetch`、ProgramData 下的错误报告队列，普通用户权限删不掉。不提权这些位置只能看不能删。

## 三步

### 1. 勾盘符，点「开始扫描」

右上角列出本机所有固定盘符，默认勾选系统盘（就是会被挤爆的那个）。

**不需要选文件夹、不需要选清理类别。** 该扫哪里是工具的事：它认识 61 个已知位置，并且明确知道哪些目录不该进（`.git`、`Documents`、`Program Files`、`site-packages`、OneDrive、凭据目录、系统区）。跳过这些让扫描少走 81 万条记录、快 30%。

### 2. 看两栏

| | 含义 | 怎么处理 |
|---|---|---|
| **可以删除**（左，绿） | 工具已经确定：已识别的厂商缓存根、确定性可再生的工具产物目录（`node_modules`、`__pycache__`、`.mypy_cache`、`.pytest_cache`、`.ruff_cache`）、超过配置天数（默认 1 天）的临时文件 | 直接清理 |
| **不确定，交 AI 判断**（右，橙） | 工具认不出这是什么 | 导出给 AI，导回结果 |

界面仍然只有两栏，不再增加第三个队列。程序或 AI 已确定不能删的项目由 KEEP 规则直接隐藏。只有 AI 明确回答 `UNSURE` 的项目才留在右栏，用户选中后可点“我来决定…”最终记为可删或保留。

左右两栏底部都有横向滚动条，可以看完整路径。也可以**双击一行**：目录会直接打开；文件会在资源管理器中被选中；如果删除后目标已经不存在，则打开仍存在的最近一级父目录。删除因占用或权限失败时，不必再手工抄长路径。

### 3. 清理

左栏每行前面有方框，**默认全部勾选**。

- 点方框可以单独取消；点行的其他地方只是高亮，不影响删除
- 「全选」/「全不选」
- 标题数字跟着勾选走：全勾显示 `53.0 GB（6,816 项）`，取消一些后显示 `48.2 GB / 53.0 GB（已勾选 6,801 / 6,816）`

两个删除按钮：

| 按钮 | 行为 | 空间 |
|---|---|---|
| **清理（进回收站）** | 交给 Windows 回收站，可从资源管理器还原 | **不释放**，要清空回收站才释放 |
| **彻底删除** | 按文件句柄直接删除，无法还原 | 立即释放 |

**点了就删，不再弹二次确认。** 勾选 + 按按钮就是你的授权。

关于回收站有一件事必须知道：Windows Shell 接受“移入回收站”请求且源文件消失后，DevClean 会比较操作前后的回收站总条目数。条目数增加时确认进入回收站；条目数没有增加时，可能是 Windows 永久删除，也可能是回收站同时淘汰旧条目或被其他进程修改。DevClean 会把后一种情况准确报告为“已由 Windows 移除，但无法确认是否进入回收站，可能无法恢复”，不会谎报一定可恢复或一定永久删除；已不存在的行会从列表移除，也不会把无法确认的空间算作已经释放。

## 交给 AI 判断

1. 右栏点「导出给 AI」，存成 JSON
2. 把这份 JSON 交给任意模型（本地模型也行），文件里带了它该怎么回答的说明
3. 点「导入结果」读回

右栏直接显示“AI 判断可能不准确，使用外部或付费模型可能产生费用”。DevClean
不会假定某个模型免费，也不会把 AI 结论自动执行为删除。

为了避免为大量同类动态文件重复付费，导出前会做一次保守合并。只有同时满足
以下条件的文件才共用一个 AI 问题：

- 位于同一目录，并且文件名中的日期、时间戳、UUID、长哈希或生成型数字能形成
  同一个受约束的通配模板；
- 分类、来源、风险、判断依据、删除权限和说明完全相同；
- 文件大小处于同一档，新旧程度处于同一档。

合并问题会把文件名模板、成员数、合计/最小/最大体积和最早/最晚修改时间写入
`similar_path_group`。AI 只有在结论适用于组内全部文件时才能回答 `DELETE` 或
`KEEP`，否则必须回答 `UNSURE`。导入时同一问题代表的每个已观察文件都会分别
写入精确结论；即使理由依赖年龄或版本而不能生成通配规则，组内成员也不会遗漏。
普通语义文件名（如 `config.json` 与 `database.json`）、不同目录、证据不同、
体积跨度明显或新旧程度不同的项目不会合并。整目录候选由程序规则直接处理，
根本不会进入 AI 导出。导出完成后的状态栏会明确显示“多少文件合并为多少个 AI
判断、减少多少个重复问题”。

模型只能回三种结论：**KEEP（不能删）/ DELETE（可以删）/ UNSURE（不确定）**。判定可删的会移到左栏，仍需你自己点删除；`UNSURE` 会留在右栏。选中这些行并点“我来决定…”，弹窗会先显示 AI 对每一项的说明，再由用户决定：

- 选择“是”：写入 `USER_DECISION` DELETE 规则，移到左栏并勾选；实际删除仍需再点清理按钮。
- 选择“否”：写入 `USER_DECISION` KEEP 规则并隐藏。
- 选择“取消”：不作修改。

导出后即使关闭并重开 DevClean，也可以直接点「导入结果」，不需要先重新扫描或重新导出。用于恢复绑定关系的会话索引集中保存在一个有上限的 JSON 中，只保存会话随机值、包摘要和候选 ID/路径，最多保留 100,000 个候选路径；完整导入且没有遗留 `UNSURE` 时会移除对应记录。有 `UNSURE` 时保留记录，方便重启后再次导入并完成用户决定。

导出包含完整路径——本地模型看不到路径根本判断不了"能不能删"。要发给非本机模型的话自己先看一遍导出内容。

同一次运行中导入时使用完整封闭校验：候选 ID 必须一对一精确覆盖，编造的、重复的、遗漏的或摘要不匹配的一律整份拒绝。结果不会因为回答耗时而过期。程序重启后没有内存中的完整导出包，备用导入仍会比对原会话 ID、随机值和包摘要，并只接受持久索引中确实存在的候选 ID；按产品决定允许逐份导入部分答案，但每个已回答项目都必须字段完整、结论合法且说明非空。两种流程都不能让模型改路径、扩大范围或选择删除方式。

## 三份可编辑规则

首次启动会在 `DevClean-data\rules\` 创建：

- `scan-rules.json`：是否扫描用户目录、已知缓存位置及其分类策略、额外扫描路径、排除路径、跳过的目录名；`delete_root_ids` 明确列出删除时连根目录本身一起移除的已知根。
- `delete-rules.json`：确定可以删除的规则。AI 导入的 `DELETE` 和用户对 AI-UNSURE 项的“可以删除”决定会写入这里。
- `keep-rules.json`：确定保留的规则。AI 导入的 `KEEP` 和用户对 AI-UNSURE 项的“确定保留”决定会写入这里，并且始终优先于删除规则。

AI/用户结论会先保存一条可移植的精确规则：`C:\Users\某人`、`AppData\Local`、`AppData\Roaming` 和临时目录分别改写成 `%USERPROFILE%`、`%LOCALAPPDATA%`、`%APPDATA%`、`%TEMP%`，路径中编码的用户名改写成 `%USERNAME%`。因此同一份规则复制到另一个 Windows 用户或另一台电脑后仍按各自实际目录展开，不包含生成规则时的用户名。

当路径中含日期、时间戳、UUID、长哈希或生成型数字 ID 时，还会生成保留其稳定目录和扩展名的 `path_glob` 同类规则，第二天生成的新文件或换了随机名的同类文件不再重复询问 AI。若同一形态后来出现相反结论，通配规则会被撤销，只保留各自精确结论。明确写着“超过多少天”“今天”“正在使用”“长期未使用”“当前/旧/最新版本”或“被新版本取代”的 DELETE/KEEP 依赖当时上下文，不会被扩成覆盖其他日期或版本的通配规则。

同一目录还会生成 `DevClean-default-rules-backup.zip`，里面是随当前版本提供的三份原始规则。规则编辑器中的“恢复默认配置”可以一键还原，用户也可以手工解压查看。

默认 KEEP 文件还包含配置化前就存在的保护基线：Codex/Claude 的会话、项目历史和配置，编辑器 `globalStorage`/`Local History`，`.env/.env.*`，以及私钥、证书和密码库文件。这些内容确定不删，也不会浪费 AI 判断次数。明确的 Claude/Codex `cache`、`plugins/cache` 子目录仍按清理规则识别，不会被状态保护规则一起隐藏。

右上角“规则设置”可以直接编辑三份 JSON，也可以点击“打开规则文件夹”后用编辑器或 AI 审定。保存后 DELETE/KEEP 的 `rules` 立即重新应用；扫描范围、阈值和分类表从下一次扫描开始应用。

如果外部编辑导致 JSON 格式错误，“规则设置”会显示磁盘上的原始内容，用户可以直接在 UI 中修正，不会用默认配置遮住错误文本。

删除和保留规则的 `match` 支持：

- `exact_path`：一个完整路径。
- `path_prefix`：某个目录及其全部后代。
- `path_glob`：完整路径通配符。
- `filename_glob`：只匹配文件名，例如 `*.tmp`。
- `path_regex`：用正则表达式搜索完整路径。忽略大小写，路径分隔符统一写成 `/`。
- `filename_regex`：用正则表达式搜索文件名，忽略大小写。

正则表达式会在程序启动或 UI 保存时预先校验并编译。表达式有语法错误时整份配置不会生效，界面会指出具体是第几条规则；不会等扫描到一半才报错。

三份文件都有明确人工分组：

- 扫描规则用 `skip_directory_groups` 和每个已知根的 `group` 分类。
- DELETE/KEEP 的内部分列表用 `classification_groups` 分类。
- DELETE/KEEP 的每条路径规则都必须填写 `group`；AI 导入统一写入 `ai_import` 组，用户对 AI-UNSURE 项的最终决定写入 `user_decision` 组。

分组名称和分组顺序也保存在 JSON 中，保存规则或导入 AI 结论时会原样保留，不会被 Python 中的隐藏默认值覆盖。`classification_groups` 可以重新组织，但必须把对应 `classification` 的每个字段恰好列出一次。

每份文件还带有 `_ai_editing_contract`。给 AI 编辑时直接提供完整文件，合同要求它只返回完整 JSON、不得使用 Markdown、不得增删或改名字段、不得修改文档类型，并在不确定时不新增规则。程序不只依赖提示语：顶层、分类表、已知根和每条规则都使用严格字段白名单，多一个字段、少一个字段、重复 ID、无效枚举或无效正则都会整份拒绝。

例如，下面的删除规则可以覆盖任意用户目录中名称为 `Cache`、`Code Cache` 或 `GPUCache` 的目录内容，而不需要给每个文件保存一条规则：

```json
{
  "id": "browser-cache-directories",
  "group": "browser_cache",
  "enabled": true,
  "match": "path_regex",
  "value": "/(Cache|Code Cache|GPUCache)/",
  "source": "USER",
  "reason": "可重新生成的浏览器缓存目录",
  "updated_at": ""
}
```

一条手工规则的写法如下；`id` 只要在当前文件内便于辨认即可，`source` 使用 `USER`，不想删除规则时也可以先把 `enabled` 改成 `false`：

```json
{
  "id": "keep-my-build-output",
  "group": "project_overrides",
  "enabled": true,
  "match": "path_prefix",
  "value": "D:\\work\\important-project\\build",
  "source": "USER",
  "reason": "这是我需要保留的构建产物",
  "updated_at": ""
}
```

`scan-rules.json` 的 `include_known_cleanup_roots` 改为 `false` 后，本文件中配置的已知缓存路径即使位于用户目录下面也会从遍历中剪掉。已知清理目录、分类、策略和标签全部在本文件的 `known_cleanup_roots` 中管理。Windows、ProgramData 或 Windows.old 下确实允许清理的条目使用 `allow_inside_system_anchor: true`；没有这个标记的相邻系统路径仍会被执行层拒绝。`delete_root_ids` 只允许引用 `known_cleanup_roots` 中已有的 ID；默认仅列出 `windows-old`，因此 Windows.old 会作为一个完整目录清理，而 Windows Temp、Prefetch、Windows Update 下载和 WER 仍只清理各自根内的内容。

`review_sample_per_category` 控制每个分类最多进入界面审核和 AI 导出的项目数，原始规则为 500。扫描仍遍历配置范围，但只保留每个分类中体积最大的这批候选，避免一次把几万条小文件交给付费 AI。AI 或用户作出 DELETE/KEEP 结论后会写入可移植精确规则，并在适用时附加同类动态路径规则；下次扫描同一路径或同一生成形态直接按规则分类，不再重复询问。

`delete-rules.json` 中的 `thresholds` 和 `classification` 是确定可删分类的唯一数据来源；`keep-rules.json` 中的 `classification` 是确定不删分类的唯一数据来源。两个文件的 `rules` 可继续添加精确路径、前缀、通配符或正则规则。执行层对 Windows 关键目录、本机固定卷、重解析点和文件身份的检查不是分类配置，不会被配置文件绕过。

AI 的明确删除/保留结论合计最多沉淀 100,000 条。AI 自己的 `UNSURE` 不直接写入删除或保留规则，仍会留在不确定列表；只有用户随后明确作出的最终决定才写入 `USER_DECISION` 规则。三份规则文件是后续扫描和分类的唯一配置，程序只接受当前 `schema_version=3`。

## 删除时的安全边界

不是靠"你确认过"，是靠删除那一刻的复核：

- 每个普通文件在删除前重新核对 **卷序列号 + 128 位 file ID + 大小 + 时间戳**。扫描和删除之间文件被替换掉就拒绝那一项，不会误删替换进来的东西。
- 整个目录作为一个对象删除时，先确认它仍是扫描时看到的同一个目录对象；目录内容可以正常变化，但同路径目录被替换就拒绝。遍历实现**不进入重解析点**——`node_modules` 里的 junction / 符号链接（`npm link`、pnpm 造的）按链接自身处理，不会把链接目标当作目标树的普通子目录继续遍历。
- 删除意图先写进 SQLite 日志再产生副作用；崩溃后不会自动重放。
- 某一项因占用、权限或扫描后变化而不能删除时，会记录失败原因并继续处理下一项；只有执行层明确确认成功的行才从左栏移除，失败项继续保留并可再次点击重试。
- 只处理本地固定卷上的普通文件和目录，不碰网络盘、可移动盘、云占位文件。

删除进度分成两个阶段：先显示候选身份准备的 `已处理/总数`；彻底删除整目录时继续显示当前第几项以及目录内已处理的文件数。移入回收站在准备阶段同样显示准确数量；进入 Windows 回收站接口后，由于 Windows 不提供目录内部逐文件计数，进度条保持动画并显示当前第几项，不会再停在“正在准备”。

## 已知限制

- 只支持 Windows 11 x64
- 回收站模式不释放空间，这是回收站的性质
- 整个目录删除**不是原子的**：中途失败或取消时，已删掉的部分无法恢复
- 扫描期间文件在变（比如缓存正在写），删除时会拒绝变化的那些项，属正常
