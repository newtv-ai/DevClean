# Visual Studio IDE storage audit

DevClean treats Visual Studio's per-instance user-data tree as mixed IDE state. Only exact subtrees with source-backed regeneration semantics receive deletion authority.

Source-audited boundaries:

- Current Visual Studio extensibility documentation places the MEF composition error log inside `%LOCALAPPDATA%\Microsoft\VisualStudio\<instance>\ComponentModelCache`, confirming that `ComponentModelCache` is per-instance MEF composition state rather than project data.
- Microsoft troubleshooting guidance instructs users to close Visual Studio, remove/rename `ComponentModelCache`, and restart Visual Studio to rebuild/reset the MEF cache. Microsoft Q&A guidance repeats this boundary for Visual Studio 2022 (`17.0_<InstanceID>`) and Visual Studio 2026 (`18.0_*`).
- DevClean therefore recognizes only existing Visual Studio 2019/2022/2026 instance selectors (`16.0`, `17.0`, `18.0`, with optional hexadecimal instance suffixes) under `%LOCALAPPDATA%\Microsoft\VisualStudio` and delegates the exact `ComponentModelCache` subtree.
- The rule requires `devenv.exe` to be closed. A process-query failure is treated as "in use" rather than granting deletion authority.
- The surrounding instance directory is not a cache boundary. Files such as `privateregistry.bin`, other per-instance state, settings, licensing state, extensions, and unknown siblings are not claimed by this rule.
- `%APPDATA%\Microsoft\VisualStudio\<instance>\ActivityLog.xml` is troubleshooting evidence generated by `devenv /Log`; it is deliberately outside this cache rule.
- Project-local `.vs`, `bin`, and `obj` directories remain project-owned and are not inferred globally from their names. MSBuild cleanup stays project-aware.
- Roslyn storage under `%LOCALAPPDATA%\Microsoft\VisualStudio\Roslyn` is deliberately deferred to a separate audit. Microsoft support guidance describes it as regenerable analyzer cache with a possible load-time cost, but this PR does not broaden the ComponentModelCache rule to that shared location.

Conclusion: exact per-instance `ComponentModelCache` roots are `IDE_CACHE` / VENDOR_MANAGED / TOOL with a closed-Visual-Studio process guard. The containing Visual Studio instance tree receives no generic recursive deletion authority.
